# Audit de l'existant - Palimpseste Electron (2026-09-13)

Branche auditée : `feat/wiki` (198 commits, ~24 500 lignes TS/TSX, 168 fichiers). Objectif : base factuelle avant une refonte majeure.

Méthode : 6 audits parallèles en lecture seule (architecture, pagination, persistance, UI/UX, Univers/IA, outillage), puis vérification manuelle des affirmations les plus lourdes (marquées **[vérifié]**). Les autres constats citent `fichier:ligne` et sont vérifiables en une minute.

---

## 1. Verdict en une page

**Ce qui est bon et qu'il faut garder**
- Le cœur pur `src/shared/` (markdown, wiki, export/printHtml) : sans dépendance Node/Electron, 130 tests verts, 0 erreur `tsc` en `strict`.
- `projectPaths.ts` + `saveRecovery.ts` : écriture atomique, journal begin/commit, chemins vérifiés, testés.
- Sécurité Electron de base : `contextIsolation: true`, `nodeIntegration: false`, `spawn` sans shell, fenêtre d'impression sandboxée.
- Export DOCX et PDF vectoriel (`printToPDF`) : fonctionnels et validés visuellement.
- Système de tokens CSS sémantiques (HSL, papier blanc/crème/sépia, clair/sombre) : la base d'un design system existe.
- Le concept produit (pagination livre + Univers/bible IA sous charte stricte) reste différenciant.

**Ce qui est dangereux aujourd'hui (données de l'auteur)**
1. **Le codec Markdown perd du contenu.** Listes, citations, blocs de code : sérialisés en chaîne vide. Souligné, surligné, barré, alignement : perdus. Un manuscrit dont les paragraphes sont séparés par un simple retour à la ligne (102 chapitres sur 103 de Savana) est aplati en un paragraphe par chapitre à la première sauvegarde. **[vérifié]**
2. **Toute sauvegarde réécrit tous les chapitres**, et l'autosave part sur `isDirty || statsDirty` toutes les 30 s. Ouvrir Savana, taper un mot, attendre : 102 chapitres irréversiblement aplatis (backups du journal purgés au commit). **[vérifié]**
3. Fichier illisible (iCloud évincé, conflit Dropbox) = chapitre retiré du manifeste puis **fichier supprimé comme orphelin** ; JSON corrompu = réécrit `[]` (toutes les fiches personnages effacées).
4. Suppression de chapitre sans confirmation ; `trash/` et `snapshots/` créés mais jamais utilisés.
5. Aucune sauvegarde à la fermeture (Cmd+Q perd jusqu'à 30 s à 5 min de frappe).

**Ce qui viole la charte IA**
6. L'agent Claude Code d'ingestion tourne en `--permission-mode acceptEdits` avec `cwd` = racine du projet, sans restriction d'outils ni de répertoire : il peut écrire dans `chapitres/`. **[vérifié]**
7. Deux actions IA génèrent de la prose « utilisable directement dans un roman » (`locationEnrich.ts`, `characterEnrich.ts`).

**Ce qui bloque la distribution**
8. Electron 28 (version courante 44, support terminé), 39 vulnérabilités prod dont une critique (`jspdf`, qui n'est même plus importé), pas de signature/notarisation macOS (Gatekeeper bloque l'app chez quiconque d'autre), pas d'auto-update, pas de CI, 0 test renderer.

**Le problème historique (pagination)**
9. Le « saut » a des causes identifiées et localisées dans `tiptap-pagination-plus` (lib solo, 600 lignes, 0 test) : repagination synchrone 3 layouts par frappe, reconstruction totale du DOM au changement de nombre de pages, pas d'hystérésis, mesures faussées par le zoom, virtualisation qui gonfle le flux. **[zoom et virtualisation vérifiés]** Corrigeable en vendorisant la lib (effort M), sans changer de moteur.

### 2.2 Éditeur et pagination

Mécanisme réel : une seule vue ProseMirror ; la lib insère un widget `#pages` de N cadres, chaque cadre = un float `.page` de largeur 0 et de `margin-top` = hauteur de page + un float `.breaker` pleine largeur. Le texte coule et est repoussé sous chaque breaker : **les paragraphes sont bien coupés ligne à ligne par exclusion CSS** (contrairement à ce que dit `PAGINATION_ARCHITECTURE.md`, qui décrit l'ancien système supprimé au commit `3261fde`).

| Sév. | Constat | Preuve |

## 3. Plan d'upgrade proposé

Ordre dicté par le risque : d'abord ne plus perdre de texte, ensuite un socle sain, puis les chantiers produit. Chaque phase = une branche, typecheck + tests + vérification visuelle avant merge.

### Phase 0 - Arrêter l'hémorragie (S, avant tout le reste)
- Codec sans perte : supporter listes/citations/code/règle, marks underline/highlight/strike/code, `textAlign` ; pour tout nœud/mark inconnu, sidecar JSON ou bloc `palim-json` ; test de propriété `parse(serialize(doc)) = doc` sur tous les nœuds enregistrés dans l'éditeur.
- Parseur : `\n` simple = nouveau paragraphe (Savana) ; `ref.id` prioritaire sur l'id frontmatter.
- Ne jamais dégrader en silence : lecture échouée → chapitre « illisible », jamais retiré ni supprimé ; JSON corrompu → refus d'écrire + `.corrupt-<date>`.
- Confirmation à la suppression + corbeille réelle (`trash/<date>-<file>.md`).
- Flush sur `before-quit`/`close`.
- Sauvegarde incrémentale par dirty-set (hash), vérification mtime avant écrasement.
- Restreindre l'agent : `--add-dir wiki/`, `--disallowedTools` ou hook `PreToolUse` refusant tout chemin hors `wiki/` ; snapshot de `wiki/` avant run, diff après → `created/appended` réels → undo réel.
- Supprimer `generateSensoryDetails`, réécrire `characterEnrich` ; garde-fou charte commun à toutes les actions.
- `npm uninstall jspdf html2canvas date-fns class-variance-authority @radix-ui/*` inutilisés ; `npm audit fix` ; corriger `CLAUDE.md`.

### Phase 1 - Socle technique (M)
- Vitest (projet node pour shared/main, jsdom pour renderer), migration des 31 tests, colocalisation dans `src/shared/**`, fin de la compilation dans `dist/`. Cible : stores, `lib/analysis`, `lib/stats`, `docxExporter`, codec.
- ESLint flat config + typescript-eslint typé + Prettier + `lint-staged` ; `tsc -b` incluant `main` dans `build`.
- CI GitHub Actions : typecheck, lint, tests, audit high, build `--dir` matrix.
- IPC unique typé `src/shared/ipc.ts` (canal → `{req, res}`), validation runtime des payloads, `assertProjectScopedPath` partout.
- CSP + `setWindowOpenHandler(deny)` + `sandbox: true` + ErrorBoundary racine et par panneau + log dans `app.getPath('logs')`.
- Montée de versions, une PR par étape : Electron 28→44, electron-builder 26 (ou electron-vite), Vite 8, puis React 19 / Zustand 5 / recharts 3 / react-leaflet 5. TipTap 3 + pagination-plus 3 **après** la Phase 2 (ou rendu inutile par la vendorisation).
- Éclater `projectStore` : `lib/project/io.ts` avec une seule `loadProjectFromPath`, `saveProject` découpé, notifications dans un `notificationStore`, suppression du mode navigateur, cycle wikiStore ↔ projectStore cassé.
- Supprimer la pagination legacy (~700 l.), `projectAggregator.ts` ; déplacer `components/ai/actions` → `lib/ai/actions` ; scinder `Sidebar.tsx`.

### Phase 2 - Pagination (M)
Vendoriser `PaginationPlus.js` (MIT, 600 l.) dans `src/renderer/lib/pagination/` et corriger dans l'ordre : (1) instrumenter zoom + virtualisation pour confirmer ; (2) ignorer les transactions sans `docChanged`, coalescer en un rAF ; (3) diviser les mesures par l'échelle ; (4) hystérésis d'une demi-ligne + ajout/retrait du seul dernier cadre au lieu de reconstruire `#pages` ; (5) ancrage du caret (rect avant, correction `scrollTop` après) ; (6) supprimer le double décompte en-tête et la virtualisation actuelle ; (7) réécrire `PAGINATION_ARCHITECTURE.md` pour le mécanisme float réel. Ne pas ouvrir la pagination par lignes (veuves/orphelines) tant que le besoin n'est pas exprimé ; ne pas changer de moteur.

### Phase 3 - Couche IA et Univers (L)
- Orchestrateur unique en main (`src/main/ai/`) : `Engine { run(request, onEvent, signal) }`, implémentations claudeApi (SDK, streaming, retry, abort), claudeCode, codex, gemini, ollama ; événements typés vers le renderer.
- Sortie structurée (tool use / JSON schema) à la place de `=== SUGGESTION ===` ; sortie brute persistée dans `wiki/_runs/` ; blocs rejetés affichés.
- Table de modèles à jour (claude-fable-5-1, claude-opus-5, claude-sonnet-5, claude-haiku-4-5-20251001), `maxTokens` explicite ≥ 8k, `addUsage` centralisé, historique persisté.
- Unifier sheets → wiki : `sheetsToFiches` en migration one-shot avec sauvegarde, `SheetsPanel`/`AIPanel`/`GlobalMapView` sur `wikiStore`, puis suppression de `project.sheets` (~800 l.).
- Brancher l'existant : Interroger l'Univers, graphe, tableau mystères, templates, lint de santé ; compagnon Écriture contextuel (`sceneEntities`).
- Ensuite seulement : Couche 2 synthèse multi-lentilles (à spécifier).

### Phase 4 - UI et design system (M à L)
- Quick wins : accents, tokens success/warning/info, overrides `.dark` pour `mark`/analyse, panneau Suggestions repliable, Échap + focus trap, `focus-visible` global, menu complet (Rechercher, Projets récents, Univers), zoom menu routé vers `uiStore`.
- `components/ui/` sur Radix déjà installé : Button (cva), IconButton (aria-label obligatoire), Input, Dialog, Tooltip, Tabs ; migrer les 6 overlays.
- Rechercher/remplacer, hook global de raccourcis (⌘F, ⌘1/⌘2 Écriture/Univers, ⌘K palette), barre d'état (mots, page, sauvegarde).
- Navigation de premier niveau visible pour Écriture/Univers ; mode machine à écrire ; taille d'interface ; `prefers-color-scheme` et `prefers-reduced-motion`.
- Tailwind 4 à coupler avec ce chantier.

### Phase 5 - Distribution (S à M)
Signature Developer ID + notarisation (`@electron/notarize`, `hardenedRuntime`, entitlements), `electron-updater` + `publish: github`, workflow `release.yml` sur tag, `.command` regroupés dans `scripts/launchers/`, `.claude/settings.local.json` ignoré.

## 4. Décisions à trancher (entrée du brainstorming)

1. **Format v2** : Markdown reste la vue et un sidecar JSON devient la vérité (sans perte garantie), ou Markdown étendu seul (lisible, mais toujours une liste blanche de nœuds) ?
2. **Sheets vs Univers** : on tranche l'unification maintenant (Phase 3) ou on gèle les sheets en lecture seule ?
3. **Pagination** : vendoriser (recommandé) ou rester sur la lib et tenter TipTap 3 + pagination-plus 3 d'abord ?
4. **Agent Claude Code** : périmètre d'écriture strict `wiki/` (recommandé) ; faut-il aussi lui interdire la lecture de `chapitres/` en dehors du chapitre ciblé ?
5. **Cible de distribution** : usage perso (pas de signature) ou diffusion (signature + auto-update, coût compte développeur Apple) ?
6. **Ampleur UI** : retouches (quick wins + design system progressif) ou refonte de la navigation ?
7. **Périmètre Qt** : archiver `palimpseste-qt` définitivement ? Ses acquis restants à porter : drag-to-reorder, personas IA, style de dialogue par projet + quantification, Interroger + graphe (déjà écrits côté Electron, non branchés).
